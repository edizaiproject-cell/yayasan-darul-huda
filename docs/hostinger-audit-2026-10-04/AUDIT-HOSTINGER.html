6. Template VPS dan prosedur penerapan

Berkas: environment, systemd service, Nginx site, proxy snippet. Ganti seluruh example.org dengan domain resmi. Semua masih template; sertifikat dan path harus disiapkan lebih dulu.

  shared/uploads/           unggahan publik

# Symlink pada setiap release, sebelum build:
data -> /srv/darul-huda/shared/data
public/uploads -> /srv/darul-huda/shared/uploads
public/media -> /srv/darul-huda/shared/media
  1. Buat user sistem darulhuda tanpa hak root. Install Node 24.x, npm, Nginx dan Certbot melalui sumber tepercaya. Verifikasi path /usr/bin/node pada service. Shared directory dimiliki darulhuda, direktori 750 dan berkas 640; env root:darulhuda mode 640.
  2. Buat source rilis bersih: app, components, lib, scripts, assets, public, migrations, source-reference bila setup diperlukan, package.json/lockfile dan config. Jangan membawa node_modules Windows, dist lama, cache, log, tmp, data tes atau credential. Data existing ditransfer privat terpisah.
  3. Ambil snapshot existing saat semua penulisan dihentikan, atau gunakan SQLite online backup disertai strategi konsistensi media. Jangan sekadar mengambil file .sqlite dari proses aktif. Setup bukan pengganti migrasi data. Hanya untuk instalasi kosong, jalankan npm run setup sekali dengan akun resmi/password kuat; hapus credential bootstrap sesudahnya.
  4. Pindahkan data, uploads dan media ke shared dengan hati-hati; buat symlink pada release. Jangan menimpa shared pada deployment berikutnya. Build dengan DARUL_HUDA_DB menunjuk database staging/kosong terpisah. Runtime dapat memigrasikan DB saat import: backup sebelum pergantian versi.
  5. Di release jalankan npm ci --include=dev, typecheck, semua tes, build dan smoke test. Jangan npm prune --omit=dev untuk package saat ini: Vinext dibutuhkan saat start. Env runtime berasal dari systemd; hindari .env lama di release karena launcher memuatnya.
  6. DNS A domain utama → IP VPS; www CNAME → domain utama. AAAA hanya jika IPv6 benar-benar aktif. Pertahankan MX/TXT email. Firewall membuka 80/443 dan SSH untuk operator; port 5174 tidak dibuka ke publik.
  7. Bootstrap Nginx dengan blok HTTP saja. Sediakan location /.well-known/acme-challenge/ dengan root /var/www/letsencrypt dan buat direktori tersebut. Setelah DNS aktif, jalankan certbot certonly --webroot -w /var/www/letsencrypt -d example.org -d www.example.org menggunakan domain asli.
  8. Pasang proxy snippet ke /etc/nginx/snippets/darul-huda-proxy.conf dan site ke sites-available lalu symlink sites-enabled. Aktifkan blok TLS hanya setelah sertifikat tersedia. Jalankan nginx -t sebelum reload; sediakan default server penolak hostname asing. Template mengasumsikan Nginx sebagai satu-satunya public proxy, bukan di belakang CDN tambahan.
  9. Pasang service ke /etc/systemd/system/darul-huda.service. Set symlink current, lalu systemctl daemon-reload dan systemctl enable --now darul-huda. Periksa journalctl -u darul-huda. Validasi timer renewal dan certbot renew --dry-run.

Tidak menggunakan PM2 cluster/multi-instance/serverless. Untuk skala horizontal, migrasikan database dan media ke layanan bersama melalui perubahan kode.

8. Backup, rollback dan go-live

Usulan: backup harian dengan retensi 7 harian + 4 mingguan, salinan terenkripsi di luar VPS, serta backup sebelum update. Cara paling sederhana untuk konsistensi: maintenance singkat, hentikan service, arsipkan shared/data+uploads+media dan identitas release, kemudian hidupkan service dengan penanganan kegagalan backup. Alternatif tanpa downtime memerlukan SQLite online backup dan pengelolaan konsistensi media. RPO 24 jam/RTO 2 jam adalah target usulan, belum terbukti.

Uji restore di staging: integritas DB, login, media, bukti privat, saldo dan PDF. Rollback source saja belum tentu aman karena migrasi schema; periksa kompatibilitas atau pulihkan snapshot lengkap dengan memperhitungkan transaksi yang masuk setelah snapshot.

  • Perbaikan login, regression test dan penilaian advisory selesai.
  • Clean install/build Linux, seluruh 192 tes dan smoke production lulus.
  • Login/logout browser HTTPS, ganti password, izin editor, edit CMS, upload, konfirmasi/validasi donasi dan PDF berjalan.
  • Akun impor benar, password diperbarui, sesi lama dicabut, tanpa data uji.
  • Private media menolak anonim, database/env tidak tersaji, cache privat tidak tersimpan.
  • SITE_URL, canonical/sitemap, PWA, rekening dan kontak resmi diverifikasi.
  • Data bertahan setelah restart/redeploy; backup dan latihan restore berhasil.
  • Monitoring uptime HTTPS, 5xx, disk, RAM, log dan umur backup; renewal TLS teruji.
  • Load test sesuai kebutuhan traffic; belum ada klaim kapasitas dari pengujian lokal.

Hasil akhir: fondasi fungsional cukup baik untuk staging. ZIP belum siap upload production. Template VPS sesuai kebutuhan source saat ini, dengan perbaikan dan verifikasi go-live sebagaimana di atas.
